# qwen-colab-book-gen

Telegram-бот в Docker: присылаете ему EPUB — он запускает сборку аудиокниги через
**Google Colab CLI** в фоне, пишет о каждой стадии и в конце отдаёт архив и ссылки на Google Drive.

    вы:    [отправили kabala_na_ezoterika.epub]
    бот:   📖 Принял «kabala_na_ezoterika.epub» (1.4 МБ). Запускаю сборку в фоне — о стадиях напишу сам.
    бот:   🚀 Поднимаю машину Colab (T4) для «kabala_na_ezoterika»
    бот:   🔗 Подтвердите доступ к Google Drive: https://accounts.google.com/o/oauth2/…
    бот:   ⚙️[6/12] Нарезка по предложениям + book-text.epub
    бот:   🎧 Озвучка: 2278 сегментов, ожидаемое время звука ≈6.4 ч
    бот:   ✅ Готово за 214 мин · файлы: book.m4b и book-read-along.epub
    бот:   ✅ «kabala_na_ezoterika» готова за 214 мин. Файл в томе: /data/results/…
                     Google Drive: https://drive.google.com/drive/folders/… • …m4b • …epub

Всё, что нужно для работы, установлено **на этапе сборки образа**: Google Colab CLI из PyPI,
tmux для фоновых заданий, `attr` для ссылок Drive, и сам конвейер `qwen-epub-audiobook`.
При запуске ничего не докачивается — только читается токен бота и монтируются тома.

Образ собирается и публикуется **только на GitHub Actions** (`.github/workflows/build.yml`):
каждый пуш в `main` → `ghcr.io/davnozdu/qwen-colab-book-gen:latest` и тег с номером коммита.
Локально собирать не нужно.

## Быстрый старт

    git clone https://github.com/davnozdu/qwen-colab-book-gen.git
    cd qwen-colab-book-gen
    cp .env.example .env         # впишите TELEGRAM_BOT_TOKEN (и, если нужно, TELEGRAM_CHAT_ID)
    docker compose up -d

Дальше в Telegram:

1. напишите боту `/login` — он пришлёт ссылку; откройте её (можно с телефона), войдите в нужный
   Google-аккаунт, подтвердите доступ и пришлите боту код со страницы. Это **один раз**: токен
   сохранится в томе `config/` и переживёт пересборку контейнера;
2. пришлите EPUB — сборка пойдёт в фоне;
3. `/status` — что делается, `/jobs` — последние задания, `/log <номер>` — журнал,
   `/stop <номер>` — остановить.

Готовый архив забирается в том `data/results/`, копия уезжает на Google Drive (папка
`DRIVE_DIR`, по умолчанию `Audiobooks-colab`), и бот присылает ссылки на папку и оба файла.

## Тома

| Том | Зачем |
| --- | --- |
| `./config` → `/root/.config` | Вход в Colab (`colab-cli/token.json`, `sessions.json`) и настройки бота. Переживает пересборку и обновление образа. |
| `./data` → `/data` | `books/` — присланные книги, `jobs/` — журналы заданий, `results/` — готовые архивы и части разрезанных книг. |

Бэкапить достаточно этих двух папок.

## Настройки (`.env`)

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | — | Токен от `@BotFather`. **Один и тот же** токен работает и для приёма книг, и для уведомлений из Colab: они приходят в тот же чат. |
| `TELEGRAM_CHAT_ID` | пусто | Кому отвечать. Если пусто — владельцем становится тот, кто первым напишет боту. Несколько человек — через запятую. |
| `GPU` | `T4` | Ускоритель Colab (`T4`, `L4`, `A100` — если есть Pro). |
| `DRIVE_DIR` | `Audiobooks-colab` | Папка внутри `MyDrive`, куда складывать готовое. |
| `SHRINK_HOURS` | `7` | Книги длиннее режутся на части: первая идёт в работу, остальные уезжают на Drive в `Audiobooks-shrink` и в том; каждую обрабатывают отдельным запуском. `0` — не резать. |
| `MAX_JOBS` | `1` | Сколько сборок одновременно. У бесплатного тарифа машина одна — оставьте `1`. |

Токен в репозиторий не попадает: `.env` в `.gitignore`, в образ он приходит только из окружения
контейнера.

## Фоновые задания и освобождение ресурсов

* Каждое задание идёт в отдельной tmux-сессии внутри контейнера; журнал — в `data/jobs/<номер>/log.txt`.
* Как только сборка закончилась, сессия закрывается — ничего не остаётся висеть в памяти.
* Машина Colab в конце освобождается (`colab stop`): в контейнере это делается даже при неудаче
  (`STOP_ON_FAILURE=1`), чтобы ускоритель не занимался зря.
* Закрыли контейнер (`docker compose down`) — задания прекращаются; незавершённые книги просто
  пересоберутся при следующем запуске.

## Проверки

`tests/smoke.sh` прогоняет всё как есть: поднимает заглушку Telegram, кормит боту книгу и
проверяет, что он подтвердил приём, собрал, прислал ссылки и **не оставил ни фоновых окон,
ни процессов**. В CI этот тест гоняется на настоящем образе (там же проверяется и tmux-путь).

    RUN_LOCAL=1 bash tests/smoke.sh      # без Docker: проверяет логику бота и заданий
    bash tests/smoke.sh                  # на образе (нужен Docker)

## Полезные мелочи

* Ручной запуск в контейнере (тот же Linux-скрипт, что использует бот):

      docker compose exec bot run-book "/data/books/kabala_na_ezoterika.epub"

* Логи контейнера: `docker compose logs -f`; журнал конкретного задания — `/log <номер>` в Telegram.
* Обновление: `docker compose pull && docker compose up -d` — вход и тома остаются на месте.
* Файлы больше 20 МБ Bot API не отдаёт: положите книгу в `data/books/` и скажите боту номер
  задания… либо просто запустите `run-book` вручную (см. выше).
* Уведомления и авторизация Drive внутри задания — та же обвязка, что и в
  [qwen-epub-audiobook](https://github.com/davnozdu/qwen-epub-audiobook): ссылка приходит и в
  терминал, и в Telegram, Enter нажимается автоматически через 60 секунд, а доступ проверяется
  на самой машине.

## Если что-то не так

| Симптом | Что делать |
| --- | --- |
| Бот молчит | `docker compose logs -f` — чаще всего неверный токен или не заполнен `.env`. |
| «Вход в Colab уже есть» не срабатывает, книги не запускаются | `/usage` покажет ответ CLI; если просит авторизацию — `/login`. |
| «Service Unavailable» / «too many assignments» | Colab не выдаёт ускоритель: обёртка сама повторяет запросы с паузами, а если лимит исчерпан — придётся подождать или сменить аккаунт через `/login`. |
| «Машину получить не удалось» | То же: свободных T4 нет. Попробуйте позже или `GPU=L4`. |
| Нужно поменять аккаунт Google | `/login` заново: старый `token.json` можно предварительно переименовать в `config/colab-cli/`. |
